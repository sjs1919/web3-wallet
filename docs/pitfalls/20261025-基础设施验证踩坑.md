# 2026-10-25 基础设施验证踩坑记录

## 坑 1：gateway 路由 503 — 缺 spring-cloud-starter-loadbalancer

- **日期/场景**：启动 4 服务后，直连 8081/8082/8083 health 全通，但网关 `http://127.0.0.1:8080/api/v1/account/health` 返回 503
- **根因**：gateway pom 只有 `spring-cloud-starter-gateway` + `nacos-discovery`，**没有 `spring-cloud-starter-loadbalancer`**，`lb://account-service` 无 LoadBalancer 可解析 → Service Unavailable
- **教训**：Spring Cloud Gateway 用 `lb://` 路由时必须显式引入 loadbalancer starter；Nacos 只提供服务发现，不提供负载均衡
- **规避动作**：`gateway/pom.xml` 增加 `spring-cloud-starter-loadbalancer`，重建重启后恢复
- **是否升级**：架构事实 → 写回 api-spec / 模块依赖清单

## 坑 2：WSL 后台进程随会话退出被回收

- **日期/场景**：`nohup mvn spring-boot:run &` 后台起 4 服务，wsl bash 会话结束后进程消失，日志文件也不复存在
- **根因**：`wsl ... bash -lc "..."` 会话退出时 WSL 回收进程树；`nohup &` 不保证存活
- **教训**：
  - 长驻服务要用**保持 wsl 进程存活**的方式启动（如 harness 后台任务 `exec mvn ...`）
  - `mvn spring-boot:run` 的 java 子进程可能作为孤儿存活，但不可依赖
- **规避动作**：`deploy/start-services.sh` + `deploy/stop-services.sh`；验证时用后台任务方式，日志写 `/root/logs/web3-wallet/`
- **是否升级**：环境事实 → 已写入 `deploy/` 脚本注释
